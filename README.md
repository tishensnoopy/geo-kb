# GEO 知识库构建

为企业建立一份 AI 能准确复述的事实库，作为 GEO 内容生产的基础。

**判断一条信息该不该进库，只问一句：AI 说错了，会不会出事。** 会出事的进库；咨询量、成本、访谈家数这类不会出事的，是经营数据，不进知识库。

---

## 给 Agent 的安装指令

> 看到这里请按下面三步执行，不要跳步，也不要自己重新实现安装逻辑。

**第 1 步 · 拿到代码**

```bash
git clone --depth 1 https://github.com/tishensnoopy/geo-kb.git
```

clone 失败时按顺序重试，两个镜像可用：

```bash
git clone --depth 1 https://ghfast.top/https://github.com/tishensnoopy/geo-kb.git
git clone --depth 1 https://gh-proxy.com/https://github.com/tishensnoopy/geo-kb.git
```

**三个地址都失败时**，不要猜、不要手写文件创建，直接告诉用户：
「仓库 `tishensnoopy/geo-kb` 无法访问，可能尚未公开或地址不对。请确认仓库地址，或手动下载 zip 解压后告诉我解压路径。」

**第 2 步 · 跑安装脚本**

```bash
python3 geo-kb/scripts/install.py --target <用户项目目录>
```

`<用户项目目录>` 用户没指定就用当前目录。脚本会复制文件、建 `data/`、写 `AGENTS.md`，返回工作台绝对路径。**不联网、不装依赖、不覆盖用户已有数据。**

**第 3 步 · 按脚本返回的 `next_actions` 逐条做完**

脚本输出的 JSON 里有 `next_actions` 字段，里面是装完必须马上做的事。**不要跳过**，尤其是：

- 探测连接器 → 写入 `geo-kb/环境状态.json`
- 问用户要不要建定时提醒任务 → 用户同意就用定时任务能力真建出来，别只写进 JSON
- 用户没连任何知识库工具时，**主动告诉他缺什么**，并给替代路径（导出 Markdown 永远可用；Obsidian vault 是本机文件夹，不需要连接器）

**第 4 步 · 给用户交代清楚**

- 工作台绝对路径（`workbench.html`），以及数据在哪（`data/<企业简称>/` 下的六个 JSON）
- 怎么打开：浏览器直接打开那个 HTML 文件。改完记得点「导出变更包」，把文件交给 Agent 写回
- 如果没连任何知识库工具，现在就说，别等用户翻到工作台第 7 步才发现

**最后给用户工作台的绝对路径，并说明数据在哪。**

## 这不是什么

- 不是内容制作工具——不写稿、不做图文、不做视频
- 不是发布工具——不发平台、不铺信源
- 不是监测工具——不做复测、不做归因
- 不是托管服务——数据在客户自己机器上，我们不碰

只做一件事：**企业知识库的建立与维护**，为后续内容产出打基础。

## 适合谁用

给正在做 GEO 的从业者：GEO 服务商、企业市场负责人、内容团队，或者任何需要让 AI 准确介绍某家企业的人。

## 前置条件

- 一个能联网搜索、能读写本地文件的 Agent（WorkBuddy、Codex 等）
- 联网搜索是必需的：外部说法要靠检索发现，客户端自己开口说的不算数
- 客户愿意配合提供事实——这一条最重要，工具不能替客户凭空造事实

## 安装

把仓库地址发给 Agent，说「帮我安装这个项目」：

> 安装 https://github.com/tishensnoopy/geo-kb

Agent 会运行安装脚本，然后直接打开工作台。

或者手动：

```bash
python3 scripts/install.py --target <你的项目目录>
python3 scripts/install.py --check --target <你的项目目录>   # 只检查，不改文件
```

安装脚本做四件事：复制指令与模板、建 `data/` 数据目录、在项目根写或更新 `AGENTS.md`、返回工作台绝对路径。

**不联网、不装依赖、不修改你已有的文件。** 重复安装只补缺失文件，用户数据绝不会被覆盖。

装完你会有：

```
你的项目/
├── AGENTS.md                    ← Agent 每次开工读它，知道工作台在哪
└── geo-kb/
    ├── SKILL.md
    ├── workbench.html          ← 工作台，Agent 会帮你打开
    ├── .安装信息.json
    ├── 环境状态.json           ← Agent 探测连接器后写入，页面读它显示哪些目标可用
    ├── data/                   ← 你的数据，一家企业一个子目录
    │   └── <企业简称>/
    │       ├── 档案.json       企业基本信息与目标
    │       ├── 外部说法.json   联网检索结果，待客户对账
    │       ├── 意图.json       客户购买意图
    │       ├── 事实.json       AI 引用的依据
    │       ├── 待办.json       到期复核与待解决冲突
    │       └── 更新记录.json   改动留痕
    ├── reference/
    └── templates/{md,json}/
```

## 怎么用

**数据存在哪**：`geo-kb/data/<企业简称>/` 下的六个 JSON 文件，跟着你的项目走，可备份、可进 Git、可换机器带走。

**工作台和文件的关系**：数据源是 JSON 文件，工作台是编辑器。浏览器打开本地 HTML 时不能直接写旁边的文件，所以改完之后点「导出变更包」，把内容给 Agent，它写回文件。localStorage 只作草稿，刷新不丢但清缓存会丢——所以每次改完记得导出。

**二次启动找不到工作台**：读项目根的 `AGENTS.md`，里面记着绝对路径。就算 Skill 被删了，这个文件还在。

**定时提醒**：安装时问你要提醒频率，按每家企业自己的复核周期分别设定（不是统一每周）。Agent 用定时任务实现，任务读该企业的 `待办.json` 把到期项推给你。

## 同步到知识库工具

**页面自己探测不到 MCP 连接器**（它跑在浏览器沙箱里，看不到 Agent 的工具列表）。所以 Agent 每次会话开始会探测一次，把结果写进 `geo-kb/环境状态.json`，工作台第7 步读它显示每个目标能不能用。

| 目标 | 需要什么 | 怎么获得 |
|---|---|---|
| ima 知识库 | 官方 ima 连接器 | 连接器管理里搜索「ima」安装并授权 |
| Obsidian vault | **什么都不需要** | 告诉 Agent 你的 vault 绝对路径。vault 就是本机文件夹，Agent 直接读写 |
| Notion / 飞书 / WPS | 相应连接器 | 连接器管理里搜索安装 |
| 导出 Markdown | 什么都不需要 | 永远可用，任何环境都行 |

**一个云端工具都没连时会怎样**：工作台会明确告诉你「没有任何云端知识库工具可用」，并说清后果——成果停在本机文件里，内容团队拿不到，知识库也不会自动更新。同时给出替代路径：导出 Markdown 永远可用；有 Obsidian 的话连连接器都不用装。

不会静默失败，也不会假装同步成功。想让状态更新，跟 Agent 说一句「探一下我的连接器」就行。

装完第一次打开工作台，第 7 步会显示「未探测」，这是正常的——Agent 还没跑过探测。

## 开始使用

加载后直接说：

> 用 GEO 知识库构建。企业名称：……；品牌名：……；官网：……；主要业务：……；客户主要在：……；这次最想解决：……；已有的 GEO 尝试：……

Agent 会先问基本信息，然后联网检索，逐条对账外部说法，推导客户购买意图（先确认意图，再推导字段），逐条收集事实，挂上更新节奏，最后问你要不要同步到自己的知识库工具。

一次只做一家企业。企业多的时候每家一个文件夹，互不混用。

## 流程与产出

| 阶段 | 产出文件 | 说明 |
|---|---|---|
| 0 拿信息 | `企业档案.md` | 只问五项，不一次问太多 |
| 1 联网检索 | `外部说法.md` | 每条带来源、分级、日期、链接 |
| 2 逐条对账 | `外部说法.md` → `事实库.md` | 客户认了才算事实，认不了的是冲突或缺口 |
| 3 推导意图 | `购买意图清单.md` | **先给客户确认，不停在这一步往下走** |
| 4 推导字段 | `事实库.md` | 字段由客户在意的东西推出来，不套模板 |
| 5 收集事实 | `事实库.md` | 每条挂证据、标责任人、写周期 |
| 6 更新节奏 | `更新待办.md` | 会变的事实标短周期 |
| 7 同步出去 | — | 写入客户自己的 ima / Obsidian / Notion 等 |
| 8 变更留痕 | `变更记录.md` | 改了什么、为什么、谁改的 |

## 这个工具和普通知识库工具的区别

普通知识库工具给你一套字段，按格填。

这套工具**先问客户在意什么、在做什么判断、AI 说错会怎样，然后才推出该填什么**。所以：

- 客户填的每一格都对得上他真实会问的问题
- 字段因行业而异，不是一套通用模板——「客户问价格」，钢琴店、装修、软件要填的东西完全不同
- 减法类字段（明确不提供什么、不适合谁）会被主动追问，这是最容易漏、漏了危害最大的
- 客户答「这个我们不填」时，会被反问「不填的话客户问 AI 时 AI 怎么答」，多数听完就愿意填

## 能力边界

这些做不了，也不假装能做：

- **不主动推送提醒**。工具本身没有定时能力，配置定时任务后可以每周检查，否则靠打开时人工查 `更新待办.md`
- **不替客户跑 AI 实测**。真实实测由客户在目标 AI 产品里亲自执行，客户提供原始记录后可原样整理引用
- **不承诺排名、推荐或收录效果**
- **不代客户登录、付费或公开发布内容**
- **数据不离开客户机器**。没有服务端，仓库是静态文件，客户的数据都在客户本地

## 五题实测说明

Skill 能帮客户生成五个可复制的问题，并说明怎么操作（哪个产品、怎么记录日期与模式、怎么保存原文）。但**不自动运行、不模拟答案、不分析回答效果**。

一次实测只能看方向。要报「提及率」这类比例，需要同一套题在同一个产品上按节奏多轮累计，单次结果不代表客户看到的分布。

实测表现不能作为加码或停止的依据——它证明不了获客效果与投资回报。

## 常见问题

**问：一定要联网搜吗？**
是。客户自己说的和网上公开说的可能不一致，这个不一致往往就是 AI 会说错的地方。不联网就发现不了。

**问：客户手上没有客户问句记录怎么办？**
用访谈补采。推导客户购买意图的依据可以是销售记录、客服记录、访谈，或客户口述的成交流程。**不要凭空编客户行为。**

**问：数据会被上传吗？**
不会。这个工具没有服务端，数据全在客户本地文件里。

**问：一家企业做完了能换下一家吗？**
可以，在下建一个文件夹。企业之间不共享内容，也不会互相污染。
