# 事实库

> 阶段二产出。这是 AI 会引用的内容。**每条都要能对应到一条已确认的购买意图。**
>
> **入库标准**：这条内容能不能让 AI 在该意图对应的客户提问下，说出一句有出处、不出错的话。能，才算完成。

## 推导记录

字段不是通用模板，是从客户意图推出来的。写清推导过程，客户才能判断该不该填。

```
客户在意：
要做的判断：
AI 说错的后果：
所以需要的事实：
```

## 事实 N · <字段名>

- **对应意图**：意图 N（**一条事实可同时服务多个意图，写「意图 1、意图 5」**）
- **事实内容**：一句话，能被独立引用
  > 写给 AI 读，不写给客户看。判断标准：一个从没接触过这家企业的读者，只看这一句能不能准确转述。
- **来源类型**：企业自述 / 客户原件 / 内部整理
- **证据**：文件名、链接、合同条款、客户授权
- **提交人**：
- **审核人**：
- **入库时间**：
- **更新责任人**：具体的人或岗位，不是「公司」
- **更新周期**：每月 / 每季 / 每半年 / 每年 / 不变
- **最近复核**：
- **谁能提供这条**（待补时填）：前台 / 财务 / 主诊医师 / 品牌方 / 负责人 / 外部

< 如由外部说法对账而来，注明原来源与确认日期 >

> **一条事实挂多个意图时**，导出或渲染时只写一次，第二个意图下写「见意图 N：<字段名>」，不要重复整条内容。

## 待补事实

对账或填字段过程中发现的缺口。**关键是「谁能提供」——客户往往不是不愿意填，是不知道该找谁要。**

| 缺什么 | 为什么重要 | 谁能提供 | 什么时候要 | 状态 |
|---|---|---|---|---|
| | | | | 待补 |

>「谁能提供」按实际情况填：前台、财务、主诊医师、品牌方、负责人、外部机构。
> 客户能立刻说清找谁，这一条就补上了；说不清的，工具应该帮客户列「要资料清单」让他去催。

## 检查

- [ ] 每条事实都对应至少一个已确认的购买意图
- [ ] 每条都是一句话，能被独立引用，不是整段介绍
- [ ] 每条挂了证据
- [ ] 每条有更新责任人和更新周期
- [ ] **明确不承诺什么**——有内容，不是空的
- [ ] **明确不适合谁**——有内容，不是空的
- [ ] 没有任何无证据的表述（行业第一、经验丰富、专业团队）
- [ ] 没有编造的案例、数据与客户故事
- [ ] 价格类事实写了口径：按什么单位、含什么、不含什么
- [ ] 所有会变的事实都标了短周期
- [ ] 客户没提过的信息没有硬塞进来
